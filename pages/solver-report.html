How the High Density Force Improve Solver Works

The solver is a local route repair pass. It does not autoroute from scratch. It takes existing high-density intra-node routes, nudges their internal points away from collisions, keeps endpoints fixed at ports, clamps everything inside the node box, and outputs improved route geometry.

Input

Routes + Nodes

`hdRoutes` provide path geometry. `nodeWithPortPoints` provides bounds, ports, and layer constraints.

Model

Mutable Points

Route points become movable nodes. Endpoints stay fixed. Coincident layer-change points become via nodes.

Improve

Forces + Projection

Repulsion fixes clearance, smoothing preserves shape, and projection resolves remaining overlaps.

Output

Updated Routes

Movable node positions are rounded back into route points and vias are re-derived from layer changes.

Mental Model

Think of each trace as a chain. The first and last links are nailed to the port points. The middle links can slide. Nearby traces and vias push each other apart. The node border pushes points back inward. Shape-restoring and smoothing forces keep the chain from becoming noisy.

Key Files

`lib/HighDensityForceImproveSolver.ts` contains the interactive solver, force pass, projection pass, and route materialization.

`lib/repair.ts` wraps the solver in a repair pipeline: original DRC, endpoint normalization, simplification, force improvement, then selecting the best stage.

`lib/utils/normalize-routes.ts` uses port points to make route endpoints attach to the expected ports and layers before force improvement.

`lib/drc-check.ts` validates endpoint attachment, bounds, trace-trace clearance, via-trace clearance, and via-via clearance.

Step-by-Step Flow

1. Assign routes

The constructor receives many `nodeWithPortPoints` and many `hdRoutes`. For every route, it checks whether all route points and vias fit inside a node plus a small margin. If multiple nodes contain the route, it picks the smallest node.

2. Build mutable route graph

Each route point becomes a `MutableNode`. The first and last point are fixed so ports do not drift. Consecutive points with the same x/y but different z become one via node with boundary padding.

3. Build collision objects

Mutable nodes become force elements: either normal route points or vias. Adjacent mutable nodes become segment obstacles. Segments are indexed by layer with Flatbush so nearby checks are fast.

4. Apply forces

The loop applies via-via repulsion, point/via-to-segment repulsion, border repulsion, shape restoration, path smoothing, route tightening, and endpoint-orthogonal cleanup.

5. Clamp and project

After each force step, points are clamped to node bounds. Then a projection pass directly separates remaining via-via and point/via-segment penetrations by small capped corrections.

6. Materialize output

Mutable node positions are copied back into route point arrays, coordinates are rounded, and vias are re-derived wherever a route changes layer at the same x/y coordinate.

Forces Used

Force Purpose
Via-via repulsion Pushes vias from different nets apart.
Point/via-segment repulsion Pushes points and vias away from nearby foreign traces.
Border repulsion Keeps geometry from hugging or crossing node edges.
Shape restore Pulls points toward their original positions.
Smoothing + tightening Reduces jagged paths and pulls redundant bends toward a straighter chain.

Why Projection Exists

Force simulation is gradual. It can reduce overlaps but still leave tiny violations after a step. Projection is the hard correction layer: it measures penetration and moves movable points just enough, capped by small maximum corrections. This makes the solver less dependent on perfectly tuned force constants. 

for each node:
  select routes inside node bounds
  repeat N steps:
    compute repulsion / smoothing / border forces
    move only non-endpoint nodes
    clamp nodes inside bounds
    project remaining clearance violations
  final projection
  copy mutable points back into routes

How This Relates to `cmn_632`

The focused `cmn_632` fixture is intentionally small: one node, two port points, and one route between them. That case is useful for understanding fixed endpoints and node bounds. With only one short route there is little collision pressure, so the solver mostly proves that the route is assigned, clamped, preserved, and materialized correctly. Larger samples show the more interesting force behavior because multiple nets compete for space.
